## Notes / assumptions

- Native side uses no mjlab code (observation, reference lookup, JointPositionAction, reset state, rsl_rl actor re-implemented in native_dance.py, imported unchanged); flip metrics use rl/eval_flip.cum_pitch (imported).
- Rollouts run from frame 0 for T-1 = 189 policy steps (the last frame mjlab serves before it re-samples); no terminations, so a failed flip is played to the end and judged by the success rule.
- Knee torque: native = actuator_force of both knee actuators after every mj_step; mjlab = the same field read after every mujoco_warp substep (env.sim.step wrapped). 'unclipped demand' = kp (ctrl - q) - kd qd at the pre-step state; the applied force is clamped to the forcerange (+-120 N.m for the knees) in both sims.
- Scenario runs: start jitter, push and seed per run index are identical across scenarios (paired comparison). The jitter is part of every scenario incl. 'nominal'; the exact-start run is listed separately.
- Latency in the scenario suite: fixed lag in physics steps (4 = 20 ms, 8 = 40 ms), history filled with the first policy target; mjlab's DelayedActuator instead outputs ctrl 0 rad for the first `lag` substeps after a reset (measured above), which matters only right after the reset.
- Clamped-actuator damping: in MuJoCo C 3.5 (implicitfast; hand check in the diag table) an actuator whose force is clamped by forcerange contributes no -kd term to the implicit velocity derivative; mujoco_warp keeps -kd for every actuator (MuJoCo 3.16 was not hand-checked, but its closed loops and warp-clamp emulation runs equal the 3.5 ones in the tables). This was not checked for the dance policies. The forward pass (actuator / bias / constraint forces, qacc) agrees; the next velocity differs on steps with a clamped actuator (ankle / waist / hip pitch / wrist pitch at take-off and in flight). 'warp-clamp emulation' reproduces mujoco_warp in native MuJoCo by switching forcelimited off and choosing ctrl so that the PD force at the pre-step state equals the clamped force.
